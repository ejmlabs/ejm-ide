what it does

Built around the code you write.

Both themes use the ejmlabs palette. Preferences picks System, Light or Dark, and the editor theme follows.

Source comes first

A Monaco editor in resizable groups, with one tab bar per group and movable tabs. Source, diffs and Markdown previews share the main editor.

Follow the whole story

Definitions, implementations, references, callers and callees come from your language servers. Links from the local index are labelled inferred.

A call graph you steer

The graph for the selected method starts shallow. More callers and More callees on a node reveal the next branch.

Git in the workspace

Stage files, commit the reviewed index, search a paginated commit graph, and follow file history and blame, including unsaved text.

Edi, an agent you can inspect

Tool progress, arguments, results and recorded file diffs appear in chat. A Debug inspector shows agent timing, failures and limits.

Split editors

Open several editor groups side by side and move tabs between them.

languages

Language servers do the reading.

ejm-ide starts a server when you open the first file of a language, and sends unsaved text to it before each lookup. Hover, completion, definitions and formatting follow what the server advertises.

Open the project root.

Servers read your build files from the root. Ruby LSP does not advertise call hierarchy, so Ruby graphs rely on the local index and say so.

limits

Honest about what it knows.

Semantic links come from language servers. Links from the local index are labelled inferred, and partial results say so instead of hiding the gap.

note

These are the documented defaults of the current build, taken from the project's language guide. They are limits, not speed measurements. No benchmark against other editors has run, and a finished crawl shows static relationships, not proof of every runtime call.
